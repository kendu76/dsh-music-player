# 新闻播报 · UI / 交互设计

> 范围：`docs/daily-news-briefing-design.md`（已确认）中 Web 端部分的界面与交互定稿。
> 原则：新闻是「讲书家族」的第二个成员——**凡讲书已有的交互心智，一律原样继承**；
> 新闻特有的只有两处新界面：面板「新闻播报」页签、播放条的类别目录弹层。
> 状态：已确认。

## 1. 设计原则

1. **复用讲书心智**：类别 = 章节、期次 = 一本书、条目 = 句子。用户学会过 AI 讲书，就会用新闻播报，零学习成本。
2. **播报为主、阅读为辅**：声音是主出口；面板文字版用于「错过了/想细看/想挑着听」。
3. **不新增视觉语言**：全部复用现有样式类（`.dsh-music-tab` / `.dsh-music-track` / `.dsh-music-toc` / ghost 按钮等），不引入新颜色与新组件范式。

## 2. 入口与信息架构

面板左侧竖排页签（`.dsh-music-tabs`，88px）插入「新闻播报」，位置在 **AI讲书之后、系统配置之前**：

```
┌────────┐
│ 本地音乐 │
│ QQ音乐  │
│ 酷狗音乐 │
│ AI讲书  │
│ 新闻播报 │  ← 新增（active 态高亮同现有）
│ 系统配置 │
│ 关于    │
└────────┘
```

- 新闻页签**不显示** `DirectorySetting`（目录选择行，新闻无目录概念），与 qq/kg/config/about 同规则。
- 内容 pane 常驻渲染 + `display:none` 切换（`paneStyle('news')`），保持与其它页签相同的状态保留策略。

## 3. 面板「新闻播报」页签（两层结构）

### 3.1 第一层：定时状态行 + 期次列表

期次列表上方新增**常驻「定时」状态行**（定时规则的入口与状态摘要）：

```
┌──────────────────────────────────────────────┐
│  ⏰ 每日定时  08:00 播报 · 12:30 静默 · 18:00 播报 › │   ← 定时状态行（常驻）
│ ────────────────────────────────────────────  │
│  ● 今天 · 18:00        [▶ 播放]              │   ← 今日最新一期，置顶；「●」=今日已生成
│    热点 5 · 国内 3 条 · 国际 3 · 科技 3           │   ← 类别 chips（小字次要色）
│  ──────────────────────────────────────────  │
│  昨天 · 09:00                                 │
│    国内 4 条 · 国际 3 · 科技 3 · 财经 3          │
```

> 注：**RSS 信源池无任何 UI**（无状态行、无配置入口）——由 Host 在后台自动懒拉取使用，
> 每次新闻收集执行前自动获取最新池数据，无需用户配置（RFC docs/news-rss-pool-rfc.md）。
│  05-28 · 09:00                               │
│    …                              [🗑]       │   ← 行尾悬停出现删除（二次确认）
└──────────────────────────────────────────────┘
```

- **定时状态行**：左「⏰ 每日定时」，中间摘要（各定时任务时刻 + 是否勾选「收集后立即播放」，
  如 `08:00 播报 · 12:30 静默`），右「›」进入定时规则编辑器（§4）。未设置时摘要显示
  「未设置 · 点击配置」。
- **收集与播放分离的展示约定**：无论定时任务是勾选播放还是静默收集、也无论是对话还是定时产生，
  **收集结果一律进入本列表**（一期一行）。静默收集产生的、尚未播放过的期次标「待播」徽标
  ——这就是「收集好的数据列表」，用户从这里选择某一期播放（点行进详情，可播整期、播某类、
  或点某一条新闻单独播）。
- **布局**：定时状态行与最近失败提示**固定在滚动区上方**（带分隔线的工具栏），滚动条
  从卡片列表顶部开始、与卡片对齐；滚动只发生在卡片流里，状态行不随内容滚走。
- **多任务混合展示**：不同定时任务/手动触发的期次在列表中**按时间倒序混排**（接口按
  createdAt 降序返回，最新在最上）。定时任务期次标题由 Host 确定性命名为
  「M月D日 HH:MM 新闻播报」（按时刻区分定时任务），对话直接播报的期次保留 agent 命名，
  配合类别 chips 自然区分；v1 不做按任务分组或筛选（保留策略上每组独立 7 期，
  见功能设计 §3）。
- **播完自动切回原内容**：音乐/讲书/在线曲目播放中，新闻推送（定时任务自动播报或面板
  「▶ 播放整期」）打断时，客户端先快照被打断的来源；新闻期次**自然播完**后自动
  切回——讲书从进度续播，音乐/在线曲目从断点继续（各来源进度本就由 savePlayback
  分键持久化，恢复直接借用现有续播机制）。新闻期间用户手动切走/停止则放弃恢复。
- 每期为一张**卡片**（两行布局）：第一行标题（含「待播/正在播」徽标），第二行日期时间
  （今天显示「今天 · HH:MM」，更早显示「MM-DD · HH:MM」）+ 类别/条数 chips；卡片任意
  位置可点进入详情（右侧 ▶/🗑 按钮独立，不会误触）。
- 「▶ 播放」直接开播该期（等价于点进详情后的播放整期）。
- **今日徽标**：当天已生成期次的第一行行首显示「●」主题色圆点；若当期**尚未播放过**，
  圆点旁附「待播」小徽标（开播后消失）——覆盖「定时/静默收集时浏览器没开」与
  「静默收集后用户补播」两类场景。
- 空态（居中，`.dsh-music-empty` 同款）：

```
还没有新闻简报。
在对话框对我说「播报今天的新闻」即可生成；

也可以说「每天早上 9 点播报新闻」设置每日定时。
```

### 3.2 第二层：期次详情

进入方式：点击期次行。左上「← 返回」回到列表（同 QQ 面板的 head 返回模式）。

```
┌──────────────────────────────────────────────┐
│ ← 返回          今日新闻播报 · 05-30 09:00     │   ← head 固定不滚
│            [▶ 播放整期]  [🗑 删除]              │
│ ┌──────────────────────────────────────────┐ │
│ │ 国内要闻（3）                        ▶    │ │  ← 类别头：点击 ▶ 从该类第一条开播
│ │  1. xxxxx通过xxxx决议                     │ │  ← 条目行：序号 + 标题
│ │     新华社 · 摘要首行截断…                │ │  ← 来源 + summary 单行省略（次要色小字）
│ │  2. …                                    │ │
│ │ 国际（3）                            ▶    │ │
│ │  4. …                                    │ │
│ │ …（滚动区，只有条目列表滚动）                │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

- **条目行点击 = 跳播**：从该条目对应的音频块开始播（条目 ↔ 块映射 `itemChunk[]` 由 Host meta 提供）；正在播的条目行高亮（同歌单正在播样式）。
- **类别头 ▶**：从该类别第一条开播（等价讲书跳章）。
- 「▶ 播放整期」：从开场白开播。
- 删除：二次确认弹窗（复用 `ConfirmModal`）；正在播放的期次被删除则先停止播放。
- 若条目正在合成中，对应行尾显示迷你「合成中…」；失败显示「⚠ 重试」。
- **「文字版」按钮**（head 行，播放整期旁）：进入文字版阅读视图（§3.3）。

不方便听语音时直接读——由结构化数据（`categories/items`）实时渲染的文章版，

│ ──────────────────────────────────────────  │
│  国内要闻                                     │   ← 类别小节标题
│  1. xxxxx通过xxxx决议                         │
│     摘要完整展示（两三行，不截断）。              │
│     —— 新华社 · 08:02                        │   ← 来源行（次要色）
│  2. …                                        │
│  AI                                          │
│  5. …                                        │
│  ──────────────────────────────────────────  │

- **条目序号全局连续**（与播报顺序一致）；播放中打开此视图时，正在播的条目同步高亮，

### 4.1 交互细节

- **新闻采集模型**（「启用每日定时」下方）：provider → model 两级下拉，数据来自
  `GET /dsh-music/news/models`；不选 = 跟随当前活跃会话模型。该模型用于创建专用
  「新闻简报」会话（见 §4.2），保存在 `schedulePrefs.model`。
- **定时任务行**：时间为 `<input type="time">`（步进 1 分钟）；**「收集后立即播放」勾选框，
  默认勾选**——勾选 = 到点收集并自动开播（`autoplay:true`）；不勾选 = **静默收集**
  （只生成/更新期次不出声，进入待播列表，见 §3.1）。**「仅工作日执行」勾选**（编辑弹窗内）
  开启后卡片在时间旁显示「工作日」徽标，Host 定时器按**工作日历**判断（法定节假日不跑、
  周末调休补班照常，见下方「仅工作日（定时任务级）」）。行尾 [▶] **立即执行**、[🗑] 删除
  （至少保留一个定时任务才可启用）。
- **立即执行（▶）**：按**该定时任务当前的配置**（收集范围、是否勾选立即播放）立刻跑一轮，
  不等时刻；期次标题固定为「M月D日 + 定时任务时刻 + 新闻播报」（Host 侧确定性命名）。
  点击直接 `POST /dsh-music/news/run-now`（agents 服务不可用等失败时回退为复制指令，
  用户发送给 agent 后按规则执行，走 `news_broadcast`）。**手动触发不受「仅工作日」限制**
  ——用户明确触发时周六/周日也能跑。
- **执行中状态与防重复触发**：收集运行时列表页签状态行显示「· {定时任务 id|手动} 收集中…」，
  定时编辑器内所有定时任务的 ▶ 置灰并显示 **⟳**（title「收集进行中，请稍候」），5s 轮询
  自动恢复。服务端为**单收集槽位**：运行中再触发（`run-now` 或定时到点）一律拒绝
  （`busy`，不新建执行会话），定时撞车跳过本轮并留日志；`runState` 带 10 分钟 TTL，
  agent 漏报失败时自动复位不会卡死。同一定时任务冷却窗（10 分钟）内重复提交仍会被
  `news_broadcast` 工具层跳过，`force` 可强制重收（见功能设计 §5.1）。
- **添加定时任务**：弹窗新增，默认 `08:00 · 新闻条数 8 · 勾选立即播放 · 不勾选仅工作日 · 不选任何类别`；上限 6 个
  （成本与可读性平衡，超出置灰）。定时任务列表**按触发时刻升序**排列（与创建先后无关，
  面板展示与持久化顺序均已归一化）。
- **新闻条数（定时任务级，编辑弹窗内设置）**：单期收集条数上限，数字输入 1–20，**默认 8**。
  **多类别尽量平均分配**：若定时任务选择了多个类别（预设类别 chips + 自定义主题合计），
  总条数在各类别间均摊（如 8 条 × 3 类 → 3/3/2，余数给靠前类别）；单类别则全部归该类
  （可超过默认每类 8 条的上限）。触发指令会把本期条数与配额写进收集指令，工具层另按
  配额兜底收敛（见功能设计 §7.2）。
- **仅工作日（定时任务级，编辑弹窗内设置）**：勾选后该定时任务**只在「工作日」**到点定时执行——
  周一至周五扣除**法定节假日**（放假不跑），**周末调休补班视为工作日照常执行**；判断依据
  按需自动联网获取的节假日日历（timor.tech——**仅在到点判断该定时任务、且日历缺失/过期时才
  查询**，失败回退内置 2025/2026 官方表 / 周一至周五，**无需任何手工维护**，见功能设计
  §7.6）。卡片上显示「工作日」徽标。适合「工作日早 8 点播报、周末/节假日不打扰」这类
  场景。**不影响手动「立即执行」**——点 [▶] 随时可跑，不判工作日/节假日。
- **收集范围（定时任务级，编辑弹窗内设置）**：
  - **预设类别 chips**：热点（排第一，跨领域+热度排序）/ 国内 / 国际 / 科技 / 财经 / 体育 / 娱乐 多选；
  - **自定义主题**：自由文本 tag（如 `AI`、`新能源汽车`、`美股`），每定时任务 ≤ 5 个。
    **输入即生效**：不必按回车，保存时自动收进主题（回车只是立即转为 chip 的快捷方式）；
    输入框非空同样满足「范围必填」。主题词双重语义——**搜索关键词**（agent 以「日期 + 主题 + 新闻」组合查询）与
    **期次类别名**（期次里出现以主题命名的类别，来源优先该主题的权威垂直媒体，
    如 AI → 机器之心 / 量子位，见功能设计 §8.3）；
  - **范围必填**：至少选中一个类别或添加一个自定义主题，否则「添加/保存」置灰不可点
    （不显示提示文案，以按钮态表达）。「全局默认类别」已退役：定时任务范围不再有
    「继承默认」语义；旧数据里 scope 为空的定时任务由 Host 规整为全选六类。
- **自动保存**：编辑即 500ms 防抖写入 Host 端定时偏好
  （`POST /dsh-music/news/schedule`，持久化在 prefs），Host 据此重建自维护定时器。
- **定时任务数**：编辑器底部与状态行展示「N 个定时任务」；无同步语义（Host 自维护）。
- **总开关关闭**：保留配置、摘要显示「已停用」；Host 定时器停止触发。

### 4.2 生效通路（面板保存 → Host 定时器 → 每次执行新建执行会话）

**保存即生效（已重构，为默认路径）**：面板「保存」写入定时偏好
（`POST /dsh-music/news/schedule`），Host 端据此**重建自维护定时器**（`rebuildTimer`：
读 `schedulePrefs.shifts`，Node `setInterval` 每 30s 检查，到点触发 `runCollection`）——
无需 agent 创建/同步 DSH 定时任务、无需手动开会话。
每次执行（定时到点 / 面板「▶ 立即执行」`POST /dsh-music/news/run-now`）都经统一入口
`runCollection` **新建一个「执行会话」**（`ctx.agents.create`，模型取「新闻采集模型」
选择器或当前活跃会话，`setup` 里 mount 默认 preset 以装配 `web_search` 等），再把收集
指令作为 user 消息通过 `agent.followup()` 注入该执行会话。结果（期次/失败）绑定该
执行会话 id；**删除某期新闻时联动销毁它对应的执行会话**。
agents 服务不可用/创建失败时 `runCollection` 返回 fallback（面板提示）。

> 为什么不再用 DSH 会话级 schedule：schedule 是 session-local 的，依赖承载会话存活，
> 与「每任务新建会话 + 删新闻连带删会话」冲突。改为 Host 进程自维护定时器（宿主常驻、
> Node `setInterval` 可靠），完全脱离会话存活，会话销毁不影响每天到点触发。

## 5. 播放条新闻模式

当前曲目 id 形如 `news:<editionId>` 时进入新闻模式（`isNews`），条形外观与讲书同构：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📰 今日新闻播报 - 国内要闻          [展开控件时→] 34%  ⏮ ⏯ ⏭ ⏹ 📖 🔊 ☰ │
│    ~~~~~~~~~~~~~~~~字幕逐句滚动区（闲置态显示）~~~~~~~~~~~~~~~~~~~~~~~~~  │

## 7. 关键交互流

**流 A · 对话即时播报（主路径 = 收集完即播）**
```
用户:「播报今天的新闻」
 → agent web_search×N + 整理 → news_broadcast 工具（收集完立即播放，对话触发恒为 autoplay:true）
 → Host 持久化期次 + pendingIntent{kind:'news'}
 → 客户端 intent 轮询命中：加载 meta → 播放条切新闻模式 → 从开场白开播
 → 面板若已打开：自动切到「新闻播报」页签并进入该期详情（条目高亮跟随播放）
   面板未打开：不强行弹开，播放条已有完整反馈
```
对话中也可以只要收集不播放：「收集一下今天的新闻，先别播」→ agent 提交时
`autoplay:false` → 期次进入列表标「待播」，用户随时从面板选择播放。

**流 B · 每日定时（浏览器开着）**：同流 A，起点是 schedule 提醒驱动的 agent；播放与否由
该定时任务「收集后立即播放」勾选决定——勾选则播（同流 A），不勾选则静默收集后期次标「待播」。
聊天区会出现本轮收集的整理过程，用户可在会话里追问「把科技去掉了，重新播」→ agent 重新提交 → 同一期次被替换重播。

**流 B′ · 面板配置定时（与流 B 的衔接）**：
```
第一层点「⏰ 每日定时 ›」→ 定时规则编辑器：加/删定时任务、勾选「收集后立即播放」（默认勾选）、点「保存」
 → 偏好写入 Host；Host 据此刻重建自维护定时器（保存即生效，无需同步）
 → 此后每个定时任务到点由 Host 定时器触发，新建执行会话走流 B
```
注意：定时器由插件在 DSH 主机进程内自维护（读已保存的定时任务偏好，每 30s 检查、到点触发），
完全脱离会话存活——每次执行新建一个独立「执行会话」收集并绑定结果，会话销毁不影响每天
到点触发；删除某期新闻会连同删除它对应的执行会话（见功能设计 §7.5）。

**流 C · 错过/回看（收集好的数据列表）**：打开面板 → 新闻播报页签 → 列表里「待播」徽标的期次
（定时没听到 / 静默收集的都在这）→ 点行进详情 → 点「▶ 播放整期」，或点类别 ▶ 播某类，
或点某一条新闻从该条开始播。

**流 D · 播放中操作**：📖 跳类 / ⏮⏭ 换类 / 🔊 换声音（当前块重合成后无缝续播，断点字符位置不变）/ ⏹ 停止；刷新页面后期次与块位置从 prefs 恢复（讲书同款断点续播），播放条立即显示 `N%` 进度。

**流 E · 定时任务手动立即触发**：
```
定时规则编辑器里某定时任务点 [▶ 立即执行] → POST /dsh-music/news/run-now
 → Host 走统一入口 runCollection：新建执行会话并注入该定时任务收集指令（不等时刻）
 → 期次照常入列表；若勾选播放则同流 A 开播
```
与定时触发的唯一差别是不等时刻、由用户手动拉起；配置不需先「保存」也可立即执行
（按编辑器当前未保存的值执行）。

## 8. 状态与反馈汇总

| 状态 | 呈现位置 | 形式 |
|---|---|---|
| TTS 未配置 | 新闻页签顶部 | 提示条「未配置 xiaomi 提供方，简报可阅读不可播」（期次仍生成） |
| 搜索服务未配置 | 新闻页签底部提示区 | 与 AI 语音提示分行显示：「新闻收集需要 DeepSeek 搜索服务（web_search 使用 DeepSeek 官方 API），请在 DSH 设置中配置好再使用。」——未配置 DeepSeek 搜索时收集无法进行 |
| 块合成中 | 播放条名称后 + 条目行尾 | `合成中… Ns` 递增计数 |
| 块合成失败 | 播放条 | 错误文案 + 「重试」按钮（讲书同款） |
| 待播 | 期次列表行 | 「待播」小徽标（已收集未播放：定时错过/静默收集），开播后消失 |
| 定时任务执行中 | 定时状态行 + 编辑器定时任务行 | `⟳ 收集中…`（▶ 按钮禁点，TTL 10 分钟自动复位）；完成后出期/报失败 |
| 定时任务收集失败 | 定时状态行下方 | 「⚠ 今天 12:30 定时任务收集失败 · \<错误摘要\>」——原因透传工具错误码与消息（不做诊断），附通用排查指引；最近 10 条，agent 经 `news_schedule` `reportFailure` 回写；**任何一次收集成功后自动清空**（问题恢复即消失，重启/刷新不残留）；行尾「✕」可**手动清除**（`POST /dsh-music/news/failures/clear`，无需等下一次收集） |
| 定时任务数 | 定时状态行 / 编辑器 | 「N 个定时任务」；无同步语义（Host 自维护） |
| 正在播条目 | 详情列表 + 目录弹层 | 高亮（同歌单正在播样式） |
| 空态 | 新闻页签 | 引导文案（见 §3.1） |

## 9. 明确不做（v1）
