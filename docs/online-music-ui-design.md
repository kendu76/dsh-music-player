# 在线音乐（QQ 音乐）· UI 设计实现

> 目标：在 dsh-music-player 现有播放器上叠加「QQ 音乐」在线能力（登录、歌单、排行榜、新歌、搜索、收藏）。
> 状态：**已实现**。本文档描述落地后的实际 UI 与交互。
>
> 使用前提：**需扫码登录**（QQ 登录或微信登录）。未登录时仅显示登录入口。

## 1. 信息架构

```
播放面板
├─ 顶部 tab： [本地音乐] [QQ音乐] [AI讲书]     ← QQ音乐 为在线入口
│     └─ QQ音乐 tab（两层）：
│          第 1 层 · 主 UI（登录 + 浏览 + 搜索 + 播放）：
│          ├─ 未登录：两个居中登录按钮（QQ登录 / 微信登录）+ 免责声明
│          └─ 已登录：顶部工具栏 + 6 个子 tab

│          第 2 层 · 播放列表 UI（当前队列 / 某歌单详情，返回 + 可滚动歌曲列表）
```

## 2. 登录

### 2.1 入口与形态

- 未登录时 QQ 音乐 tab 仅显示两个**居中大按钮**（QQ 登录 / 微信登录，分两行）+ 风险免责声明。
- 点按弹「QQ 音乐登录」模态（全屏遮罩）：显示二维码 + 状态文案 + 「刷新二维码 / 取消」。

### 2.2 两种登录方式

| 方式 | 流程 | 适用 |
|---|---|---|
| **QQ 登录** | `ptqrshow` 取二维码 → `ptqrlogin` 轮询 → 成功 | 大陆 IP 较稳 |
| **微信登录** | `open.weixin.qq.com` 取二维码 → 长轮询 → 微信扫码 → 换 cookies | 各地可达，推荐 |

### 2.3 登录状态机

```
closed ──▶ generating ──▶ waiting ──▶ scanned ──▶ success ──▶ main UI
                          │            │
                          ├─▶ expired ─┴─▶ regenerating
                          └─(取消/关闭)──▶ closed
```

- 成功：`Set-Cookie` 由 Host 捕获并持久化（`~/.dsh/music-player-qq-cookie.json`，0600），
  cookie 不进浏览器；刷新后仍登录。
- 登录成功后强制刷新「我喜欢」收藏集合。

### 2.4 免责声明

> 登录前明确提示：「扫码登录走第三方接口，仅供个人试听。登录及播放存在账号风控、封禁与合规风险，
> 请知悉并自行承担后果；如有顾虑请勿登录。」

## 3. 主 UI（登录后）

### 3.1 顶部工具栏

```
┌──────────────────────────────────────────┐
│ [ 播放列表 ]              [ 退出登录 ]  │   ← 同款 ghost 样式，左右各一
├──────────────────────────────────────────┤
│ 我的歌单 | 推荐歌单 | 分类歌单 | 排行榜 | 新歌 | 搜索 │   ← 6 个子 tab
└──────────────────────────────────────────┘
```

- 默认落在「我的歌单」tab。
- 只有子 tab 内容区滚动，工具栏固定。

### 3.2 歌单卡片（我的歌单 / 推荐歌单 / 分类歌单 / 搜索结果中的歌单）

```
┌────────────────────────────────────────┐
│ [封面图]  歌单名                       │  ← 56×56 圆角封面（lazy，失败自动隐藏）
│           创建者 · 12 首 · 播放 3.2万   │
└────────────────────────────────────────┘
```

- 卡片式：封面图 + 名称（加粗）+ 元信息（创建者 · 歌曲数 · 播放量）。
- 悬停边框/背景高亮为绿色主题色。

### 3.3 各子 tab 行为

| 子 tab | 内容 | 备注 |
|---|---|---|
| **我的歌单** | 当前账号创建/收藏的歌单（卡片） | 默认 tab |
| **推荐歌单** | 热门推荐 12 条（卡片） | 底部「加载更多」→ 全部分类分页续载（去重） |
| **分类歌单** | 分类 chips + 分类下歌单（卡片） | chips 默认折叠显示 8 个，可「展开全部」（60+ 类）；歌单支持「加载更多」 |
| **排行榜** | 榜单分组 → 榜单卡片 → 榜单详情歌曲 | 卡片含榜单封面（frontPicUrl）；详情页有返回 + 榜单名/更新时间 |
| **新歌** | 新歌速递歌曲列表 | 最新/内地/港台/欧美/韩国等 |
| **搜索** | 搜索框 + 历史下拉 + 结果（歌曲/相关歌单双 tab） | 历史持久化 localStorage（最近 10 条） |

### 3.4 歌曲行

```
▶ 晴天  [VIP]                周杰伦
```

- 歌名（播放中 `▶` 前缀）；**VIP 徽标紧跟歌名后**（金色，不参与省略截断）。
- 行尾统一显示**歌手名**（与 VIP/非 VIP 一致）。
- 点击播放；播放中再点 = 暂停/恢复。

## 4. 播放列表 UI（第 2 层）

- 由「播放列表」或点歌单卡片进入；顶部「← 返回」+ 当前来源名 + 歌曲数（+ 描述）。
- 歌曲列表可滚动；点击播放，同第 3.4 行样式。

---

## 5. 收藏「我喜欢」

- 播放条上的**爱心按钮**：在线曲目点击 → 加入/移出 QQ 音乐「我喜欢」（dirId 201）。
- 判断当前曲目是否已收藏：`songmid` 优先、`songid` 兜底；读取失败回退本地兜底集合。
- 已收藏歌曲爱心实心点亮；切换歌曲实时刷新。
- 登录成功/收藏/取消后同步本地集合。

## 6. 数据流与状态

### 6.1 路由（Host）

见 [online-music-feasibility.md](online-music-feasibility.md) §3 完整清单。核心：

| 用途 | 端点 |
|---|---|
| 登录/状态/退出 | `/dsh-music/qq/login/*`、`/dsh-music/qq/status` |
| 搜索 | `/dsh-music/qq/search?w=` |
| 播放（同源流） | `/dsh-music/qq/play/<songmid>` |
| 歌单 | `/dsh-music/qq/playlist-*`、`/dsh-music/qq/playlists`、`/dsh-music/qq/my-playlists` |
| 发现 | `/dsh-music/qq/top-lists`、`/dsh-music/qq/top-songs`、`/dsh-music/qq/new-songs` |
| 收藏 | `/dsh-music/qq/fav`、`/dsh-music/qq/liked` |

### 6.2 前端状态（局部 useState，位于 QQOnlinePanel）

| 状态 | 说明 |
|---|---|
| `loggedIn` / `uin` / `nickname` | 登录态（`loggedIn` = cookie 是否存在，不等于「能播 VIP」） |
| `qqAuthExpired` / `kgAuthExpired` / `ncAuthExpired`（store） | **播放失败判定**：在线曲目整列都播不出来（单曲失败只自动跳下一首）且该家原本已登录 → 判定「疑似登录失效」，停止跳歌并把面板切回登录 UI，提示「登录可能已失效，请重新登录」。**不做主动探测**（探测判不准会误报，见 feasibility §6）。差异只在登录 UI 形态：QQ 整面板两个入口由用户选（用 `loginFrom` 提示上次方式）；酷狗/网易云单一扫码 → 自动打开二维码。重新登录成功后复位该标记 |
| `browseTab` | 当前子 tab（`mine|recommend|category|tops|new|search`） |
| `layer` | 主 UI / 播放列表 UI（`main|playlist`），并持久化 |
| `recommended` / `minePlays` / `categories` / `catPlays` | 歌单数据 |
| `topGroups` / `topDetail` / `newSongs` | 排行榜/新歌数据 |
| `q` / `results` / `plResults` / `hist` | 搜索 + 历史 |
| `catExpanded` / `catPage` / `recPage` 等 | 折叠/分页 |
| `qqFaved` / `qqFavIds` / `qqFavMids` | 收藏状态 |

### 6.3 播放持久化

- 在线播放进度（当前曲目 + 队列 + 来源 + 时间戳）存 localStorage，刷新后恢复、可续播。
- `scope` 持久化为 `{ kind: 'qq' }`。

## 7. 场景与边界

| # | 场景 | 处理 |
|---|---|---|
| 1 | 未登录 | 只显示登录按钮，不展示浏览/搜索 |
| 2 | 已登录点「退出登录」 | 清 Host cookie + 前端态，回到登录页 |
| 3 | 歌单封面加载失败 | 图片隐藏，退化为纯文字卡片 |
| 4 | 榜单无歌曲 | 显示「该榜单暂无歌曲。」 |
| 5 | 推荐/分类歌单翻到底 | 「加载更多」自动隐藏 |
| 6 | 分类 >8 个 | 折叠显示 8 个 + 「展开全部」；可收起 |
| 7 | 搜索无结果 | 显示「未找到相关结果。」 |
| 8 | VIP 歌曲未登录 | 登录后播放（vkey 取链） |
| 9 | 刷新后恢复在线播放 | 恢复当前曲目/队列/来源，点 ▶ 续播 |
| 10 | 收藏读接口失败 | 回退本地持久化集合，爱心状态仍可靠 |
| 11 | 在线曲目整列都播不出来且原本已登录 | 判定「疑似登录失效」→ 停止跳歌 + 面板切回登录 UI（QQ 两个入口由用户选；酷狗/网易云自动出码），播放条提示「无法播放（可能是登录已失效），请重新登录」。**不做主动探测**：不刷新页面、不播放就不会发现（也正因如此不会误报） |
| 14 | 酷狗业务接口报 20028（临时风控） | 不登出（只有 20017/20018 才是登录失效），避免一次抖动把用户踢下线 |
| 15 | 重新登录成功后 | 清掉「疑似登录失效」标记，面板回到主 UI（QQ/KG 的扫码态由各自登录流程复位） |
| 12 | 在线歌曲加载失败 | 自动跳下一首；**整列都失败时停下报错**。跳过计数只在**真实起播**（`playing` 事件）时清零——不能挂在 `play` 上：加载失败的源同样会先派发 `play`，用它清零会导致整列无限回绕切歌（实测事故：QQ 登录过期后整列 VIP 取链 404，播放条无限跳歌、不报错、停不下来） |
| 13 | 在线取链失败 | 一律 404（不做「是不是登录过期」的判定）；单曲失败自动跳下一首，整列失败才按第 11 行处理 |
